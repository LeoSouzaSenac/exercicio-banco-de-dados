⚔️ Missão prática de Banco de Dados

Guilda SQL

O reino precisa de um novo sistema. Sua equipe foi convocada para criar o banco de dados da Guilda dos Aventureiros. A cada etapa, uma nova exigência aparece — e você deverá usar os comandos DDL corretos para manter o sistema funcionando.

CREATE DATABASE CREATE TABLE FOREIGN KEY ALTER TABLE DROP
Progresso da missão
1/
Capítulo 1
Todo grande reino começa com uma estrutura. O seu começa com um banco de dados.

🏰 A Guilda precisa de um banco

O rei decidiu informatizar a Guilda dos Aventureiros. Antes de qualquer tabela, você precisa criar o local onde todas as informações serão guardadas.

Sua missão:
  • Crie um banco chamado guilda_aventureiros.
  • Depois, selecione esse banco para trabalhar.
Você provavelmente vai precisar de CREATE DATABASE e USE.
Capítulo 2
Os primeiros aventureiros chegam para se registrar na guilda.

🧙 Cadastre os aventureiros

Guerreiros, magos, arqueiros e ladinos estão chegando. A guilda precisa guardar os dados básicos de cada membro.

Crie a tabela aventureiros com:
  • id_aventureiro
  • nome
  • classe
  • nivel
Regras:
  • ID como chave primária e automático.
  • Nome obrigatório.
  • Classe com até 50 caracteres.
  • Nível como número inteiro.
Pense nos tipos INT e VARCHAR, além de PRIMARY KEY, AUTO_INCREMENT e NOT NULL.
Capítulo 3
Missões são registradas em pergaminhos oficiais da guilda.

📜 O mural de missões

O quadro da guilda está cheio de pedidos: resgatar aldeões, investigar ruínas e, claro, caçar dragões.

Crie a tabela missoes:
  • id_missao
  • nome
  • recompensa
  • dificuldade
Escolha tipos de dados adequados para cada coluna.
A recompensa pode precisar aceitar valores com casas decimais.
Capítulo 4
Agora precisamos ligar quem participou de qual missão.

🔗 Quem participou de cada missão?

Um aventureiro pode participar de várias missões, e uma missão pode ter vários aventureiros. Precisamos registrar essas participações.

Crie a tabela aventuras:
  • id_aventura
  • id_aventureiro
  • id_missao
As duas últimas colunas deverão ser FOREIGN KEYS.
Primeiro crie todas as colunas. Depois, no final do CREATE TABLE, crie as duas FOREIGN KEY.
Evento surpresa 1
O Arquimago descobriu uma falha gravíssima no cadastro.

✨ “E A MANA?!”

O Arquimago entra correndo na sala e grita: “Como vocês criaram um sistema de aventureiros sem registrar a quantidade de mana?!”

Nova exigência:

Adicione uma coluna chamada mana na tabela aventureiros.

Você não deve recriar a tabela. Use ALTER TABLE com ADD COLUMN.
Evento surpresa 2
Algumas classes de personagem têm nomes grandes demais para o campo atual.

📏 O campo ficou pequeno

Um “Cavaleiro Arcano da Ordem do Dragão Dourado” tentou se cadastrar. O nome da classe não coube como esperado.

Altere a tabela:

A coluna classe agora deve aceitar até 100 caracteres.

Use ALTER TABLE e MODIFY COLUMN.
Evento surpresa 3
O Tesoureiro Real exige nomes de colunas mais claros.

👑 O rei quer um nome melhor

O tesoureiro diz que recompensa é muito genérico. Poderia ser ouro, gemas, terras ou galinhas. Ele quer deixar claro que o valor representa moedas.

Renomeie a coluna:

recompensa → recompensa_moedas

Procure usar RENAME COLUMN ... TO ....
Capítulo 5
Os monstros também precisam entrar no sistema. Preferencialmente depois de derrotados.

🐉 Cadastro de monstros

A guilda quer criar um bestiário para registrar as criaturas encontradas pelo reino.

Crie a tabela monstros:
  • id_monstro
  • nome
  • vida
  • nivel
Lembre-se do mesmo padrão de chave primária usado nas outras tabelas.
Capítulo 6
A guilda quer saber quem derrotou cada criatura.

⚔️ Registro de monstros derrotados

Não basta saber quais monstros existem. Agora o rei quer saber qual aventureiro derrotou qual monstro.

Crie monstros_derrotados:
  • id_derrota
  • id_aventureiro
  • id_monstro
As duas últimas são FOREIGN KEYS.
Uma FK aponta para aventureiros(id_aventureiro) e a outra para monstros(id_monstro).
Evento surpresa 4
Alguém esqueceu uma chave estrangeira. O culpado provavelmente foi o estagiário.

🤦 O estagiário esqueceu uma FK

Durante a revisão, vocês descobriram que a coluna id_monstro existe, mas sua FOREIGN KEY não foi criada.

Corrija sem apagar a tabela:

Adicione uma constraint chamada fk_monstro ligando id_monstro a monstros(id_monstro).

Use ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY ... REFERENCES ....
Evento surpresa 5
O Conselho decidiu abandonar o sistema de mana. O mago não gostou.

🗑️ A mana foi cancelada

Depois de uma longa reunião, o Conselho decidiu que não faz sentido controlar a mana dos aventureiros.

Remova:

A coluna mana da tabela aventureiros.

Use ALTER TABLE com DROP COLUMN.
Evento surpresa 6
A antiga tabela “aventuras” ganhou um nome mais explicativo.

🏷️ Mudança de nome

O bibliotecário da guilda acha o nome aventuras vago demais.

Renomeie a tabela:

aventuras → participacoes_missoes

Use ALTER TABLE ... RENAME TO ....
Evento final
Todo desenvolvedor precisa respeitar os comandos perigosos.

🔥 O reino foi destruído!

Um dragão ancestral destruiu o salão principal. O rei manda limpar os registros antigos.

Parte A:

Apague a tabela monstros_derrotados.

Parte B:

Escreva o comando que apagaria o banco guilda_aventureiros, mas não execute.

Cuidado: DROP TABLE e DROP DATABASE removem estruturas e podem causar perda de dados. Confira sempre o nome antes de executar.

🏆 Missão concluída!

Você praticou CREATE DATABASE, CREATE TABLE, FOREIGN KEY, ALTER TABLE, ADD COLUMN, MODIFY COLUMN, RENAME, ADD CONSTRAINT e DROP.

Agora mostre seu script SQL completo para o professor.
